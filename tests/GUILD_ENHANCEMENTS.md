## 下次空闲时实机验证

1. 使用单独测试配置；后台自然结束后重开私库，让新配置字段和按钮资源生效。
2. 寄养：分别设置太鼓/斗鱼最低收益，确认低于阈值的卡未进入、等于阈值的卡可选。
   普通模式仍保留主库原有收益档位与好友分组行为。
3. 懒人寄养：概率设为 1，确认只在配置的同服或跨服分组选择；先找五星以上，
   无合格目标并完成扫描后回到同一分组选四星。收益阈值仍然生效。
   若列表超时则本轮失败，不能据此直接假设高星卡不存在。
4. 关闭“领取寄养收获”，确认这项收获按钮不被点击；体力/经验盒子的开关保持分别控制。
5. 在寄养或结界育成开启“智能放入式神”，确认使用游戏自带按钮；手动式神类别不再参与本次育成填充。
   挂卡仍由原“收取前/收取后换式神”开关控制填充时机。
6. 寮宴开启“满经验自动换式神”：确认满经验标志连续两次真实检查才触发，
   “清空”成功后数量为 0/有效总数，再执行“一键放入”，两次确认有效非空数量后提交。
   式神不足时允许保留非空的部分阵容；0/0、空阵容或操作超时会取消，且本场不再重复清空。
7. 关闭全部新增开关，再确认原普通寄养、手动育成、寮宴两次每周排程均正常。

## 庭院事务独立排程

`toolkit/python.exe -B -m unittest discover -s tests -p test_courtyard_affairs.py -v`：7项隔离检查通过。

`CourtyardAffairs` 注册于日常任务，使用自己的 Scheduler，默认关闭；`Restart.harvest` 不再调用庭院事务，即使历史配置的旧开关为 true 也不会执行。旧开关保留但隐藏，便于历史备份读取。独立任务只有确认事务为空的画面才标记完成；入口缺失、超时和一键完成次数耗尽均保持未完成。点击继续使用主仓库间隔接口。

后台任务全部自然停止后重新打开私库，启用“庭院事务”并设置运行时间，再用独立测试配置确认当前庭院入口、领奖、一键完成及返回庭院。此次没有启用真实配置，也没有执行游戏任务。

## OCR 差异核对

本机 XY 使用 `paddleocr 3.7.0`、`onnxruntime 1.18.1` 和 `PP-OCRv6_medium`，检测及识别文件合计约132 MiB；私库使用 `ppocr_onnx 0.0.3.9`、`onnxruntime 1.16.3`，检测v3和识别v2文件约10.3 MiB。XY 的 RPC 会按工作线程缓存模型，默认工作线程数量参考CPU数量，可能进一步增加资源占用。模型文件大小约13倍，不代表内存或CPU必然也是13倍；本轮没有加载模型进行性能实测。保留私库既有OCR文件与依赖。
